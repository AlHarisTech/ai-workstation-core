# ADR-0008 — Compositional Verification Layer

**Status:** PROPOSED
**Depends on:** ADR-0007 (Formal Verification Bridge), ADR-0006 (Consistency Controller), ADR-0002-B (CEG Semantics)
**Layer:** Formal Methods — Compositional Proof System
**Scope:** Multi-execution, multi-agent, cross-wave verification

---

## 1. Core Thesis

```
ADR-0008 introduces compositional verification — the ability to
prove correctness properties of a complete system by proving
properties of its components (sub-FEGs) and composing those
proofs using a formal composition algebra.

A monolithic FEG for a large execution is O(n²) to construct
and O(2ⁿ) to model-check. Compositional verification reduces
this to O(m × k²) where m = number of components and k = size
of the largest component.

The system defines:
  - FEG composition operators (∥, ≫, ▷)
  - Proof lattice for partial verification ordering
  - Assume-Guarantee contracts between sub-FEGs
  - Compositional invariant synthesis across execution boundaries
```

---

## 2. The Problem ADR-0008 Solves

**Monolithic verification fails at scale:**

```
Execution with 500 nodes, 50 agents, 200 tools
  → FEG: ~1000 states, ~500 transitions
  → Model checking: state space explosion (2⁵⁰⁰ in worst case)
  → Construction cost: O(n²) = 250,000 comparison operations
  → Single failure forces full reverification
```

**Compositional verification succeeds:**

```
Same execution, decomposed into:
  5 agent-scoped sub-FEGs (~40 states each)
  10 wave-scoped sub-FEGs (~20 states each)

  → Verify each sub-FEG independently: O(5 × 40² + 10 × 20²)
  → Compose proofs using assume-guarantee: O(m × k²)
  → Single component change → reverify only that component
```

## 3. FEG Composition Operators

### 3.1 Formal Definition

```
Let A = (Sₐ, Tₐ, δₐ, s₀ₐ, Fₐ) and B = (S_b, T_b, δ_b, s₀_b, F_b)
be two FEGs. Composition operators produce a new FEG C = A ⊕ B.

Composition preserves FEG class properties:
  - C remains deterministic
  - C remains bounded_finite
  - C remains wave_synchronized (if both components are)
```

### 3.2 Sequential Composition (A ≫ B)

```
A ≫ B: B executes only after A reaches a terminal state.

Construction:
  S_{A≫B} = Sₐ ∪ S_b
  T_{A≫B} = Tₐ ∪ T_b ∪ {τ_handoff}
  δ_{A≫B} extends δₐ, δ_b with:
    For each s ∈ Fₐ (terminal state of A):
      δ_{A≫B}(s, τ_handoff) = s₀_b
  s₀_{A≫B} = s₀ₐ
  F_{A≫B} = F_b

Use: Agent A handoff → Agent B execution
Property: □(A_terminal → ◇ B_start) holds by construction
```

### 3.3 Parallel Composition (A ∥ B)

```
A ∥ B: A and B execute concurrently within the same wave.

Construction:
  S_{A∥B} = Sₐ × S_b            (Cartesian product — interleaving)
  T_{A∥B} = Tₐ ∪ T_b
  δ_{A∥B}((sₐ, s_b), t) =
    if t ∈ Tₐ: (δₐ(sₐ, t), s_b)
    if t ∈ T_b: (sₐ, δ_b(s_b, t))
  s₀_{A∥B} = (s₀ₐ, s₀_b)
  F_{A∥B} = Fₐ × F_b

Constraint: A and B must be CONFLICT-FREE (no overlapping side_effect_surface).
Conflict validates at composition time, not execution time.

Use: Two agents executing in parallel within the same wave
Property: □(¬conflict(A, B)) holds by construction (validated at composition)
```

### 3.4 Conditional Composition (A ▷_p B)

```
A ▷_p B: After A completes, B executes only if predicate p holds
in A's terminal state.

Construction:
  S_{A▷B} = Sₐ ∪ S_b
  T_{A▷B} = Tₐ ∪ T_b ∪ {τ_true, τ_skip}
  For each s ∈ Fₐ:
    if p(s):  δ(s, τ_true) = s₀_b
    if ¬p(s): δ(s, τ_skip) = s_terminal_skip  (new terminal state)
  s₀_{A▷B} = s₀ₐ
  F_{A▷B} = F_b ∪ {s_terminal_skip}

Use: Gate node branching — ESCALATE vs continue
Property: □(A_terminal ∧ p → ◇ B_start) ∧ □(A_terminal ∧ ¬p → ◇ skip)
```

### 3.5 Iterated Composition (A*)

```
A*: A repeats until a fixpoint condition is reached.
Bounded iteration — max iterations = replan_max_iterations.

Construction:
  S_{A*} = Sₐ × {0, ..., N}      (state × iteration counter)
  T_{A*} = Tₐ
  δ_{A*}((s, i), t) =
    if s ∈ Fₐ and i < N: (s₀ₐ, i+1)   # restart
    if s ∈ Fₐ and i = N: (s, i)        # terminal
    else: (δₐ(s, t), i)
  s₀_{A*} = (s₀ₐ, 0)
  F_{A*} = {(s, i) | s ∈ Fₐ}

Use: Autonomous agent replan loop
Property: □◇(i ≤ N) — iteration is bounded
```

## 5. Assume-Guarantee Contracts

### 5.1 Definition

An Assume-Guarantee (AG) contract specifies what a sub-FEG assumes about its environment and what it guarantees in return.

```yaml
ag_contract:
  contract_id: "<uuid>"
  component_id: "<feg-ref>"

  # What this component ASSUMES about its inputs/dependencies
  assume:
    preconditions:
      - "all dependencies are SUCCESS before component starts"
      - "CapabilityContract is valid for all tools in allowlist"
      - "scheduler_cursor is at correct wave boundary"
    state_predicates:
      - "ready_queue contains all nodes in this component"
      - "no conflicting side effects with parallel components"

  # What this component GUARANTEES about its outputs/behavior
  guarantee:
    postconditions:
      - "all nodes in component reach terminal state"
      - "artifacts are produced at declared paths"
      - "no sandbox violations occurred"
    safety:
      - "no node executes before its dependencies"
      - "max_tool_invocations not exceeded"
    liveness:
      - "component reaches terminal state within max_duration_ms"
```

### 5.2 Composition Rule (AG-COMP)

```
AG-COMP: If component A guarantees Gₐ assuming Aₐ,
and the environment E satisfies Aₐ,
then the composed system (E ∥ A) satisfies Gₐ.

Formally:
  (E ⊨ Aₐ) ∧ (A ⊨_Aₐ Gₐ)  ⇒  (E ∥ A) ⊨ Gₐ

Where:
  ⊨      = models/satisfies
  ⊨_Aₐ   = satisfies under assumption Aₐ
```

### 5.3 Satisfaction Semantics (AG-⊨)

The AG satisfaction relation `⊨` is evaluated over the FEG state space — not over runtime projections. This makes AG contracts formally checkable as part of the verification pipeline.

```
DEFINITION: Satisfaction (⊨)

For a sub-FEG F and an AG contract (A, G):

  F ⊨ A   (F satisfies assumption A) iff:
    ∀ reachable states s in F:
      s ⊨ A.state_predicates
    AND
    ∀ execution paths π starting from s₀_F:
      initial_state(π) ⊨ A.preconditions

  F ⊨_A G (F guarantees G under assumption A) iff:
    (F ⊨ A) ⇒ (F ⊨ G)
    where F ⊨ G means:
      ∀ reachable states s in F: s ⊨ G.safety
      AND
      ∀ maximal paths π in F: π ⊨ G.liveness
      AND
      ∀ terminal states s ∈ F_F: s ⊨ G.postconditions

Evaluation is decidable because:
  - FEG state space is bounded_finite
  - All predicates are over FEG abstract states
  - No runtime or external state is referenced
```

### 5.4 Circular Assume-Guarantee

```
For two components A and B that depend on each other
(cyclic dependency in assumptions):

  (A ⊨_A_b Gₐ) ∧ (B ⊨_Aₐ G_b)  ⇒  (A ∥ B) ⊨ (Gₐ ∧ G_b)

Requires: well-founded ordering on dependency resolution.
The CEG guarantees DAG structure → no true circularity exists.
"Cyclic" assumptions are resolved by the dependency graph itself.
```

## 4. Compositional Closure Theorem

### 4.1 Problem

CV-001 asserts that composition operators preserve FEG class properties. This is a claim, not a theorem, unless formally proven for each operator.

### 4.2 Class Definition

```
C = {FEG | FEG is deterministic, bounded_finite, wave_synchronized}

Where:
  deterministic:     δ is a total function S × T → S
  bounded_finite:    |S| is finite and bounded by construction
  wave_synchronized: transitions within a wave are independent;
                     cross-wave transitions are totally ordered
```

### 4.3 Closure Proof Obligations

**Theorem (Sequential Closure):**

```
If A ∈ C and B ∈ C, then A ≫ B ∈ C.

Proof sketch:
  - S_{A≫B} = Sₐ ∪ S_b  (finite union of finite sets = finite)
  - δ_{A≫B} extends δₐ, δ_b with τ_handoff — remains deterministic
  - Wave structure preserved: B's waves start after A's final wave
    via τ_handoff ordering
  ∴ A ≫ B ∈ C
```

**Theorem (Parallel Closure):**

```
If A ∈ C and B ∈ C and conflict_free(A, B), then A ∥ B ∈ C.

Proof sketch:
  - S_{A∥B} = Sₐ × S_b  (finite product of finite sets = finite)
  - δ_{A∥B} interleaves δₐ and δ_b — deterministic because
    A and B operate on disjoint state components (conflict_free)
  - Wave structure: A and B share the same wave — interleaving
    preserves wave_synchronized because no cross-component
    dependencies exist within the wave
  ∴ A ∥ B ∈ C
```

**Theorem (Conditional Closure):**

```
If A ∈ C and B ∈ C, then A ▷_p B ∈ C.

Proof sketch:
  - S_{A▷B} = Sₐ ∪ S_b ∪ {s_skip}  (finite union + 1 = finite)
  - δ adds τ_true and τ_skip — both deterministic (predicate p
    evaluates to exactly one boolean at each terminal state)
  - Wave structure: B's waves (or skip) follow A's final wave
  ∴ A ▷_p B ∈ C
```

**Theorem (Iteration Closure):**

```
If A ∈ C, then A* ∈ C for any finite bound N.

Proof sketch:
  - S_{A*} = Sₐ × {0..N}  (finite product = finite)
  - δ_{A*} wraps δₐ with counter increment — deterministic
  - Wave structure repeats A's wave structure N times,
    each iteration separated by iteration boundary
  - Counter bound N encoded in state space → termination guaranteed
  ∴ A* ∈ C
```

### 4.4 Closure Under Arbitrary Composition

```
By structural induction on the composition expression:

  Base:    Every atomic FEG (from ADR-0007 extraction) ∈ C
  Step:    Each operator (≫, ∥, ▷, *) preserves C (proven above)
  Conclusion: Any well-formed composition expression over
              atomic FEGs produces a FEG ∈ C.
```

### 4.5 Where Closure Can Fail

```
Parallel composition (∥) fails closure if:
  - A and B are NOT conflict-free (share side_effect_surface)
  - Then composition is REJECTED at validation time
  - No FEG ∈ C is produced → no closure violation

Iteration composition (*) fails closure if:
  - N = ∞ (unbounded iteration)
  - Then state space = Sₐ × ℕ → infinite → not in C
  - ADR-0008 requires finite N → no closure violation
```

## 6. Proof Lattice

### 6.1 Definition

A proof lattice is a partial order over verification contracts, allowing incremental verification.

```yaml
proof_lattice:
  root: "<verification_contract_id>"    # full system verification

  nodes:
    - contract_id: "<uuid>"
      scope: "system" | "agent" | "wave" | "node"
      verified: true | false | partial
      depends_on: ["<contract_id>"]     # parent proofs
      composed_of: ["<sub-contract-id>"] # child proofs composed via operators

  edges:
    - from: "<parent-contract-id>"
      to: "<child-contract-id>"
      operator: "≫" | "∥" | "▷"        # how child composes into parent
```

### 6.2 Lattice Operations

```
LATTICE_VERIFY(contract_id):
  1. If contract.verified = true: return true (cached)
  2. If contract has no children: model-check directly
  3. If contract has children:
     a. For each child: LATTICE_VERIFY(child)  # recursive
     b. If all children verified:
        - Compose child FEGs using declared operators
        - Verify composition preserves properties
        - If preservation holds: contract.verified ← true
     c. If any child failed: contract.verified ← false
  4. Return contract.verified

LATTICE_UPDATE(changed_component):
  1. Invalidate all ancestors of changed_component
  2. Re-verify only the invalidated chain
  3. Leaves below unchanged component remain verified (unchanged)
```

### 6.3 Lattice Stability Condition

The monotonicity of the proof lattice (CV-003) depends on a stability condition:

```
STABILITY: A verified (sub-FEG, property) pair (F, P) remains verified
under composition operator ⊕ if and only if:

  1. F itself is unchanged
  2. ALL sub-FEGs that F depends on (via AG assumptions) are unchanged
  3. The composition operator ⊕ preserves class C (Closure Theorem §4)

If any of these conditions is violated, (F, P) is invalidated.

Corollary: LATTICE_UPDATE only invalidates the chain of ancestors
from the changed component to the root. Components in unrelated
branches of the composition tree are unaffected.
 

This stability condition justifies the incremental verification
claim: O(depth × k²) per update, not O(m × k²) for full re-verification.

## 7. Compositional Invariant Synthesis

### 7.1 Purpose

Automatically derive system-wide invariants from component-level AG contracts.

### 7.2 Synthesis Algorithm

```
SYNTHESIZE_INVARIANTS(feg_composition):
  1. For each component C with AG contract (A_c, G_c):
     a. Extract invariants from G_c:
        - Safety: □(bad_state) translated from guarantee.safety
        - Liveness: □◇(good_state) from guarantee.liveness
     b. For each dependency edge C → D in CEG:
        - Assert: G_c's preconditions ⊆ A_d's assumptions
        - If mismatch → INVARIANT_GAP (potential composition failure)

  2. For each composition operator:
     a. A ≫ B: synthesize handoff invariant:
        □(A_terminal → B.preconditions_satisfied)
     b. A ∥ B: synthesize non-interference invariant:
        □(∀ t ∈ Tₐ, t' ∈ T_b: conflict_free(t, t'))
     c. A ▷_p B: synthesize conditional invariant:
        □(A_terminal → (p → ◇ B_start) ∧ (¬p → skip))

  3. Package synthesized invariants into a system-wide verification contract
```

## 8. Cross-Execution Composition

### 8.1 Purpose

Compose FEGs from different executions to prove properties that span multiple runs (e.g., Mode 2 → Mode 3 escalation, recovery continuity).

### 8.2 Cross-Execution FEG

```
Given FEG₁ (Mode 2 execution that escalated) and
      FEG₂ (Mode 3 execution that resumed from snapshot):

Cross-execution composition:
  FEG_cross = FEG₁ ≫ FEG₂
  handoff_condition: FEG₁.terminal_state matches FEG₂.snapshot_state

Validation:
  - FEG₂.snapshot_state ≅ FEG₁.state_at_escalation_wave
    (state equivalence under α abstraction)
  - If mismatch → COMPOSITION_REJECTED
```

### 8.3 Cross-Execution Properties

```
Properties provable across executions:
  ✓ All nodes from Mode 2 execution reached terminal before Mode 3 started
  ✓ Mode 3 execution did not re-execute completed Mode 2 nodes
  ✓ Scheduler cursor in Mode 3 correctly resumes from Mode 2 wave boundary
  ✓ Total node count across both executions = |V_CEG|
  ✓ No node is missing or duplicated across the combined execution
```

## 9. Integration with ADR-0007

### 9.1 FEG → Composition Pipeline

```
ADR-0007 produces:    FEG (monolithic, per execution)
ADR-0008 decomposes:  FEG → sub-FEGs (by agent, wave, region)
ADR-0008 composes:    sub-FEGs → verification lattice
ADR-0008 proves:      compositional properties via Assume-Guarantee
```

### 9.2 Property Preservation

```
If ADR-0007 proves P on monolithic FEG,
and ADR-0008 decomposes FEG into {F₁, ..., Fₙ} using valid operators:
  FEG = F₁ ⊕ F₂ ⊕ ... ⊕ Fₙ

Then ADR-0008 preserves:
  - Safety properties (□) across composition
  - Liveness properties (◇□) if each sub-FEG terminates
  - Determinism if each sub-FEG is deterministic and operators are deterministic
```

## 11. Complexity Analysis

| Operation | Monolithic | Compositional | Reduction |
|-----------|-----------|---------------|-----------|
| FEG construction | O(n²) | O(m × k²) | k ≪ n for large n |
| Model checking | O(2ⁿ) worst | O(m × 2ᵏ) | Exponential reduction |
| Property verification | 1 large proof | m small proofs + composition check | Parallelizable |
| Incremental update | Full re-verify | O(depth × k²) | Only changed chain |
| Cross-execution composition | Not possible | O(k₁ × k₂) | New capability |

Where n = total state count, m = component count, k = max component state count.

## 13. Decision Outcome

ADR-0008 introduces compositional verification — a formal composition algebra (≫, ∥, ▷, *) for FEGs that enables modular proof of system-wide properties. The Compositional Closure Theorem (§4) formally proves that each operator preserves the FEG class (deterministic, bounded_finite, wave_synchronized), and by structural induction any well-formed composition of atomic FEGs remains in C. Assume-Guarantee contracts (§5) define component boundaries with satisfaction semantics evaluated over FEG state space (decidable, bounded_finite). A proof lattice (§6) provides incremental verification with monotonic truth — changed components invalidate only ancestor proofs. Cross-execution composition (§8) enables verification spanning Mode 2 → Mode 3 escalation. Composition reduces verification complexity from O(2ⁿ) to O(m × 2ᵏ) where k ≪ n. All composition is sound — verified components compose to verified systems (CV-004).

---

## 14. Consequences

**Positive:**
- Verification scales to large executions by decomposing into sub-FEGs
- Incremental verification: change one component, re-verify only its ancestors
- Assume-Guarantee enables independent verification of sub-systems
- Cross-execution composition links Mode 2 and Mode 3 verification
- Proof lattice enables partial verification with clear status tracking
- Composition operators (≫, ∥, ▷, *) cover all CEG structural patterns
- Soundness preserved: composition never introduces spurious behaviors

**Constraints:**
- AG contracts must be authored per component — automation is deferred
- Parallel composition requires explicit conflict-freedom validation
- Cross-execution composition depends on state equivalence at handoff
- Proof lattice depth = CEG depth (max 128) — deep hierarchies are costly
- Composition is sound but not complete — some true properties may not be provable compositionally
- α/γ mapping errors in sub-FEG construction cascade to all composed proofs (trust anchor risk inherited from ADR-0007)
