# MCP Gateway Architecture Paper (v1.0 Final Spec Document)

## 1. Abstract

MCP Gateway is a deterministic, policy-enforced, and failure-controlled execution gateway designed to mediate interactions between an orchestration layer (e.g., OpenCode) and tool execution systems (Filesystem, Git, GitHub MCP). The system is engineered as a bounded distributed runtime with strict guarantees around execution determinism, failure isolation, latency ceilings, memory stability, and full observability.

This document defines the final v1.0 architectural state after completion of Kernel, Integration, Hardening, Observability, and Production Efficiency phases (v1.0 → v1.4).

## 2. System Goals

### Primary Objectives
- Deterministic execution of tool requests
- Fail-closed security and session validation
- Bounded resource usage (memory, CPU, latency)
- Isolation of tool failures via circuit breakers
- Full traceability of all executions
- Production-grade stability under sustained load

### Non-Goals
- No adaptive learning or AI-driven routing
- No dynamic self-optimization loops
- No kernel modification after v0.6.2 freeze
- No runtime orchestration beyond deterministic rules

## 4. Core Design Principles

### 4.1 Determinism First

All routing decisions must be reproducible given identical input. Time-based entropy and race-dependent selection are explicitly prohibited.

### 4.2 Fail-Closed Security Model

Any invalid session, malformed request, or policy violation results in immediate rejection before routing.

### 4.3 Bounded Execution

All system resources are explicitly bounded:

- memory usage per request
- latency per request
- session count
- retry budget

### 4.4 Failure Isolation

Tool-level failures must not propagate beyond adapter boundary due to circuit breaker enforcement.

### 4.5 Observability Without Side Effects

Telemetry and tracing are strictly non-invasive and must not affect execution semantics.

## 5. Kernel Layer (v0.6.2 - Frozen)

The kernel operates as a pure policy enforcement engine:

### Responsibilities
- request validation
- policy enforcement
- execution authorization
- audit trail generation

### Constraints
- no feature expansion allowed
- no execution logic ownership
- no routing responsibility

## 6. MCP Gateway Execution Pipeline

### Process Flow
1. Session Validation (fail-closed)
2. Backpressure Check
   - global saturation detection
   - session queue limits
   - tool throttling enforcement
3. Kernel Policy Evaluation (async audit)
4. Deterministic Routing
5. Circuit Breaker Evaluation
6. Retry Budget Enforcement
7. Tool Adapter Execution
8. Response Construction
9. Trace Compression
10. Telemetry Emission

## 7. Backpressure Model

### Mechanisms
- per-session queue limits
- global saturation detection
- tool-level throttling
- soft rejection before system collapse

### Behavior
- requests are rejected before resource exhaustion
- system maintains stability under concurrency spikes

## 8. Circuit Breaker Model

### States
- CLOSED: normal operation
- HALF-OPEN: recovery probing
- OPEN: failure isolation mode

### Triggers
- repeated failures
- latency spikes
- saturation indicators

### Outcome
- prevents cascading failure propagation across tools

## 9. Retry Budget System

### Structure
- global retry budget per request
- per-tool retry limits
- exponential backoff with jitter

### Constraints
- retry storms are explicitly prevented
- retry amplification is bounded

## 10. Deterministic Routing Model

### Properties
- identical input produces identical routing path
- monotonic trace identifiers
- no time-based randomness
- race-condition free resolution

### Outcome
- predictable system behavior under load

## 11. Tool Adapter Layer

### Supported Adapters
- Filesystem MCP
- Git MCP
- GitHub MCP

### Responsibilities
- normalize execution interface
- enforce retry + timeout + circuit breaker wrappers
- emit execution events to observability layer

## 13. Production Efficiency Layer (v1.4)

### Memory Efficiency
- bounded TraceGraph (max 8 events per request)
- ring-buffer telemetry storage
- bounded session lifecycle tracking

### Latency Control
- hard request latency ceiling (30s)
- fast-path execution under low load
- tracing skip under safe thresholds

### Session Stability
- max session cap (100)
- idle eviction (30 minutes)
- heartbeat lifecycle enforcement

### Kernel Signal Optimization
- read-only kernel signal access
- no feedback loops into execution logic

## 14. Failure Model

### Covered Failure Types
- partial tool failure
- timeout cascading
- retry amplification
- routing saturation
- session exhaustion

### Mitigation Layers
- circuit breakers
- retry budgets

- controlled failure propagation

- routing remains deterministic under load
