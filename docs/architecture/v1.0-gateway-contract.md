# MCP Gateway Spec v1.0

**Contract Definition: OpenCode ↔ MCP Gateway ↔ MCP Servers**

## 1. 🎯 الهدف (Purpose)

تحديد عقد تشغيل موحد (Execution Contract) بين:

- OpenCode CLI (Client Layer)
- MCP Gateway (Orchestration Layer)
- MCP Servers (Execution Providers)

الهدف الأساسي:

تحويل جميع عمليات MCP إلى Request/Response structured protocol قابل للتوجيه، التتبع، وإعادة التنفيذ.

## 2. 🧱 النظام العام (System Model)

```
OpenCode
   ↓ (MCP Request Envelope)
MCP Gateway
   ↓ (Routed MCP Call)
MCP Server (Filesystem / Git / Memory / GitHub / Fetch / Context7)
   ↓
Execution Result
   ↑
Gateway Response Normalization
   ↑
OpenCode Response
```

## 3. 📦 MCP Request Contract (OpenCode → Gateway)

### 3.1 الشكل العام

```json
{
  "id": "uuid-v4",
  "timestamp": "ISO-8601",
  "source": "opencode",
  "target": "mcp-gateway",
  "type": "mcp.request",
  "action": "filesystem.read | git.commit | memory.store | fetch.url",
  "context": {
    "project": "string",
    "workspace": "string",
    "auth": {
      "token": "string | optional",
      "scope": ["read", "write", "execute"]
    }
  },
  "payload": {
    "resource": "string",
    "parameters": {}
  },
  "meta": {
    "priority": "low | medium | high | critical",
    "timeout_ms": 30000,
    "retry": 2
  }
}
```

### 3.2 شرح الحقول

| Field | Description |
|---|---|
| id | معرف فريد لكل طلب |
| action | نوع العملية داخل MCP |
| context | سياق المشروع + الصلاحيات |
| payload | بيانات التنفيذ الفعلية |
| meta | التحكم في الأداء (timeout/retry) |

## 5. 🧭 Routing Contract (Gateway Internal Logic)

### 5.1 Rule Engine بسيط

`action prefix → MCP Server mapping`

**Mapping Table**

| Action Prefix | MCP Server |
|---|---|
| `filesystem.*` | Filesystem MCP |
| `git.*` | Git MCP |
| `github.*` | GitHub MCP |
| `memory.*` | Memory MCP |
| `fetch.*` | Fetch MCP |
| `context7.*` | Context7 MCP |

### 5.2 Routing Example

**Request:**
```json
"action": "git.commit"
```

**Gateway Behavior:**
1. detect prefix "git"
2. route to Git MCP Server
3. execute commit
4. normalize response

## 6. 🔐 Security Contract

### 6.1 Authorization Model

```json
{
  "auth": {
    "type": "bearer | api_key | mcp_signed",
    "scope": ["filesystem:read", "git:write"]
  }
}
```

### 6.2 Fail Closed Rule

- أي طلب بدون scope صحيح → Reject
- أي action غير معروف → Reject
- أي MCP server غير متاح → Fail Fast

## 7. ⚙️ Execution States

```
PENDING → ROUTING → EXECUTING → NORMALIZING → RETURNED
```

## 8. 📊 Error Model (Unified)

```json
{
  "error": {
    "code": "MCP_ROUTE_NOT_FOUND | MCP_EXEC_FAILED | AUTH_DENIED",
    "message": "Human readable message",
    "recoverable": true
  }
}
```

## 9. 🔄 Idempotency Rule

أي request يحمل نفس `id`:

- لا يعاد تنفيذه
- يتم إرجاع cached response

## 10. 📡 Streaming Support (Future-ready)

```json
{
  "type": "mcp.stream",
  "chunk": 1,
  "data": {}
}
```

## 11. 🧠 Design Principles

- Minimal Gateway logic (no business logic)
- Stateless routing layer
- MCP Servers = execution only
- Gateway = orchestration + normalization only
- Strict contract enforcement (schema-first)

## 12. 🚀 MVP Scope (What is INCLUDED)

- ✅ Request normalization
- ✅ Action-based routing
- ✅ MCP server delegation
- ✅ Unified response schema
- ✅ Error standardization

## 13. ❌ Explicitly OUT of Scope (v1.0)

- Scheduler system
- Queue system
- Metrics/observability layer
- AI reasoning inside gateway
- Caching layer advanced logic

## 14. 🧾 Summary

MCP Gateway v1.0 هو:

**Stateless routing contract layer** بين OpenCode و MCP servers

يركز فقط على:

- توحيد الطلبات
- توجيهها
- إرجاع نتائج معيارية

بدون أي تعقيد إضافي خارج نطاق التوجيه.
